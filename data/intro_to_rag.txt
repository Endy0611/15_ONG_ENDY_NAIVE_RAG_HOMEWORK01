Introduction to Retrieval-Augmented Generation (RAG)

Retrieval-Augmented Generation, or RAG, is a technique that combines a language model with an external knowledge source so that answers are grounded in real documents instead of relying only on what the model memorized during training.

A RAG system has two main pipelines. The offline pipeline runs once (or whenever documents change): it loads raw documents, splits them into smaller chunks, turns each chunk into a vector using an embedding model, and stores those vectors in a vector database. The online pipeline runs every time a user asks a question: it embeds the question with the same embedding model, searches the vector database for the chunks most similar to the question, and passes those chunks along with the question to a language model to generate the final answer.

The main benefit of RAG is that it lets a language model answer questions about private, recent, or domain-specific information without retraining the model itself. Instead of baking knowledge into the model's weights, RAG keeps the knowledge in an external store that can be updated at any time simply by re-running the ingestion step.

RAG also reduces hallucination. Because the model is instructed to answer using only the retrieved context, it is less likely to invent facts, and if the answer truly is not present in the documents, a well-built RAG system can say so instead of guessing.

A "naive" RAG system, like the one built in this homework, keeps every stage simple: fixed-size chunking, a single embedding model, a single similarity search, and a single call to the language model. More advanced RAG systems add extra stages such as re-ranking retrieved chunks, rewriting the user's query before searching, or combining multiple retrieval strategies together. These improvements sit on top of the same basic ingest -> chunk -> embed -> retrieve -> generate flow.
